Optimization notes:
 - Knapsack DP is the bottleneck (O(n*capacity)); use a 1-D table if only the value
   is needed, or scale weights / use branch-and-bound for very large vans.
 - Dijkstra is re-run for every stop; cache results or use A* / multi-source tricks.
 - NN tour can be improved with 2-opt local search (usually 5-15% shorter).
 - Sorting cost is negligible next to DP/graph steps; merge sort is kept for stability.
